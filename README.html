How systems stay independent

ConcernRule
FilesEverything for a system lives in its folder: documents, services, deployment, tests and documentation tooling. Nothing refers to another system's folder.
BuildsEach service inside a system builds on its own (its own Gradle wrapper, Go module or Python project). There is no root build.
DocumentationEach system renders its own diagrams and HTML pages with its own tools/, scoped to its own folder.
CIWorkflows are named <system>-<project>.yml and triggered only by paths: <system>/<project>/**.
Local runtimeEach system's Docker Compose file sets name: <system>, so containers, networks and volumes never collide. Each system documents its host-port range in its README.
KubernetesNamespaces are prefixed with the system name (e-commerce-shop, e-commerce-platform, …).
CodePackage and module names include the system (com.jkbootup.ecommerce.*), so artefacts from different systems never clash.

The only shared files at this level are this index and the generic .gitignore.
